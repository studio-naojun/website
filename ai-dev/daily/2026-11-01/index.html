AI開発・セキュリティ日報｜2026年11月1日号

偽ChatGPT・Claude配布ZIPのDLL悪用、GitHub Webhook送信元IP追加、Dependabot到達可能性分析とOpenAI検索障害の解消確認。

調査・編集：K.A.N.A.D.E.　／　初回確認：2026-11-01 朝JST・記事データ更新：07:01 JST

調査時点：2026年11月1日朝JST。 10月27〜30日の一次資料に基づき、見落とすと影響する条件と今日できる確認を整理した。11月1日に新たな大規模侵害が発生したという記事ではない。 最新の一次情報を必要に応じて確認する。

本日の優先対応

P1（該当者限定）： 「ChatGPT / Claudeの新しいデスクトップ版」を名乗るGitHubの非公式ZIPをWindowsで実行した場合、正規署名付きexeだけでなく同梱DLLや永続化を確認する。公式提供物全体が侵害されたという話ではない。

P2（Webhook運用者）： GitHubからのWebhookを固定の着信IP許可リストで制御している場合、GitHub公式Meta APIに追加された3範囲を確認する。自動同期済みなら原則作業不要。

P2（開発者向け）： GitHub Dependabotの「到達可能性分析」は一部のEnterprise Cloud JavaScript/TypeScript向けプレビュー。警告が「Unreachable」でも無条件に放置しない。

1. 偽AIデスクトップ配布と署名済み実行ファイルの悪用（P1：該当ZIP実行者のみ）

何が起きたか。 Check Point Researchは2026年10月27日に、ChatGPT・Claude等を模した偽GitHubプロジェクトが配布する悪性インストーラについて調査結果を公表した。攻撃者は本物の署名済みOpenAI/Anthropic実行ファイルと、不正な winmm.dll を同じZIPに入れ、利用者に実行させる。正規exeが同梱されたDLLを読み込み、Yobaと呼ばれる不正処理が動く。調査されたサンプルではローダーを通じたマイナー実行も観測された。これは非公式配布物の問題であり、OpenAIやAnthropicの公式ダウンロードが侵害されたとの発表ではない。

該当・非該当条件。 ChatGPT/Claude等の実行ファイルを模した出所不明のGitHub release ZIPをWindowsで取得し、Setup.exe などを実際に実行した場合に調査が必要。報告されたサンプルは管理者権限が必要な処理段階を含むが、「管理者で実行していないので絶対に安全」とは断定しない。単にGitHubでコードを閲覧しただけ、公式配布先から正規アプリを導入しただけでは、この報告された配布経路に該当しない。別件であるCursor Marketplace拡張混入（10月31日号）とも区別する。

起こり得る被害。 実行時のDLL読み込みからローダーや追加ペイロードが起動し、CPU資源の不正利用や持続的な実行に至る可能性がある。個々の端末の侵害や情報漏えいを、配布物の存在だけから断定しない。

今すべき対処。 非公式ZIPを使用せず、正規の製品配布経路を確認する。該当ZIPを実行した疑いがある場合、まず端末を安全に隔離して社内管理者/専門家と調査する。ZIP全体と同梱DLLの検証、Windowsのスケジュールタスク、不審な ProgramData\\WMProcess 配下の実行ファイル・DLL、プロセスと通信、セキュリティ製品の検知履歴を確認する。疑わしいものを自己判断で実行し直さない。接触した可能性のある認証情報は信頼できる別端末から調査・失効を判断する。

確認・復旧。 クリーンなインストーラで再構築し、持続化されたタスク・DLLがないか、再起動前後に再検査する。正常なアプリ署名だけでZIP全体を安全と判断しない。バックアップ復元も感染前か検証する。公式調査の対象サンプル・感染期間以外の亜種については別途確認が必要。

日時・一次出典。 調査公表2026-10-27、今朝2026-11-01 JSTに再確認：Check Point Research公式調査。

2. GitHub Webhook送信元の3 CIDR追加（P2：固定IP allowlist利用時のみ）

何が変わったか。 GitHubは2026年10月29日、github.comのWebhook送信元として次のCIDRをMeta APIの hooks 配列へ追加した：9.234.98.160/28、9.234.98.176/28、9.234.106.48/28。Webhook受信側が静的な送信元IP許可リストを固定していると、正規Webhookを拒否する可能性がある。

対象と対処。 github.comからのWebhook受信をIPベースで制限する運用が対象。Meta APIの hooks 値を定期的に同期している構成ではこの追加について通常は対処不要。固定リストの場合、公式Meta APIの現在値を信頼できるネットワーク管理経路から確認し、必要な範囲のみ許可リストに追加する。リストを無条件に全開放しない。

確認・復旧。 テストWebhookを正規手順で配送して受信HTTPとGitHub Delivery履歴の一致を確認。問題があれば直前の許可リストをバックアップから復元できるようにする一方、正当な配送を拒否しないか再検査する。Webhook署名の検証をIP制限の代わりに省略しない。GitHub Enterprise Serverなど同じ配送元ではないサービスにこの3 CIDRを機械的に追加する根拠はない。

日時・一次出典。 GitHub Changelog 2026-10-29、2026-11-01 JST確認：GitHub公式告知。

3. Dependabot Reachability Analysisの公開プレビュー（P2：任意）

何が変わったか。 GitHubは2026年10月28日、Dependabot alertsで依存ライブラリの脆弱なコードに実際に到達し得るかを補助評価する機能をpublic previewとして発表。現時点の案内ではGitHub Enterprise CloudのJavaScript/TypeScriptリポジトリ（npm/yarn/pnpm lockfileを利用）を対象に、明示的な有効化が必要。

影響と非該当。 導入しないリポジトリや対象外言語・プランの通常スキャンが直ちに変わるものではない。到達可能性が高いものから対応優先順位をつける材料になる。ただし「Potentially reachable」は到達可能性を否定できないことを意味し、「Unreachable」も利用経路やデプロイ形態の変化を見落とさないために再評価が必要。

今すべき対処・確認。 対象条件に合い、権限と運用方針が許す場合のみ試す。従来の依存スキャン・lockfile点検と合わせて修正優先順位を判断し、保留したアラートにも理由を残す。新しい検査結果と実際のアプリテスト・依存の更新履歴を照合する。元のアラート一覧・優先順位付けに戻せるよう変更履歴を保持する。プレビュー機能の提供範囲や精度は今後変わる可能性がある。

日時・一次出典。 GitHub Changelog 2026-10-28、2026-11-01 JST確認：GitHub公式告知。

4. OpenAI検索系障害は10月31日早朝JSTに解消（P2・状況整理）

何が起きたか。 OpenAI Statusは2026年10月30日19:38 UTC頃からDots、ChatGPT Workと一部ChatGPT thinking体験に検索エラーが発生したと記録。同日21:14 UTC頃（10月31日06:14 JST）に解消済み。これは11月1日に発生した障害ではなく、通常のLLM APIが一律に停止したとの意味でもない。

対処・確認。 対象時間帯に失敗した検索処理は、重複した書込み・送信が成立していないことを確認したうえで必要なものだけ再実行する。後続が依存する場合はデータ取得成功・既存結果との一致を確認。現在新たな異常があるときは別インシデントとして公式statusを確認する。

一次出典。 OpenAI公式Incident（解消報告2026-10-30 UTC）。
