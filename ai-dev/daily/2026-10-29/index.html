AI開発・セキュリティ日報｜2026年10月29日号

LiteLLM悪性配布版とPHP侵害の続報、Strands Agents Toolsの環境変数漏えい問題、AWS Lambda Brotli修正の確認手順を整理。

調査・編集：K.A.N.A.D.E.　／　確認時点：2026-10-30 朝 JST

対象日：2026年10月29日。遡及調査：2026年10月30日朝JST。この号の実際の初回公開日は公開検収後に別記する。10月29日に公開済みだったとは主張しない。

本日の優先対応

  • P0（該当環境のみ）：LiteLLM悪性配布版。10月21日の1.107.0侵害をMicrosoftが10月23日に分析、GitHub Advisoryが10月29日に更新。該当版が実行された場合は、通常のアンインストールだけでなく環境・資格情報を調査する。
  • P0（公開PHP等の該当環境）：CVE-2026-109618・CVE-2026-109619。JPCERT/CCが10月29日に、特定ファイアウォール製品で攻撃成功を示す痕跡を追記。
  • P1：AWS Strands Agents Toolsのenvironment tool。LLMの指示によって秘密値のmaskを無効化できる条件を確認。修正版0.8.6を適用。
  • P1：AWS LambdaのBrotliランタイム。10月29日JSTのAWS告知は段階修正。Node 24は単なるprocess.versionでは修正判定できない。

1. LiteLLMの悪性PyPI/コンテナ版：秘密情報漏えいの調査（P0）

事象。 2026年10月21日、PyPIと公式コンテナイメージ経由でLiteLLM 1.107.0の悪意ある配布物が公開された。Microsoftの10月23日分析では、影響環境でPythonの起動時に悪性コードが動作する場合があり、LiteLLM自体をimportすることは必須でない。10月29日に更新されたGitHub Advisoryには悪性版1.82.7、1.82.8、1.107.0が列挙された。10月29日発生の新しい侵害とは混同しない。

対象・非該当。 これらの悪性版のwheelやコンテナを取得し、実際に使用した環境。別の安全な版だけを使っている環境は当該悪性配布物の経路に非該当。バージョン文字列だけで感染は断定できず、実際に取得したwheelやコンテナdigestも確認が必要。

影響。 Pythonの起動時フック等によりcloud keys、AI API keys、開発ツールの認証情報などが読み取られ外部へ送信され得る。悪性版が混入した環境では、その環境内でPythonやpipを起動して検証すると悪性コードを再実行する危険がある。

今する対処。 清浄な別環境からパッケージ配布履歴、コンテナdigest、CIログを点検し、疑いのある環境を隔離。証拠を保全したうえで信頼済みイメージから再構築し、アクセス可能だった資格情報を適切な権限者が失効・再発行する。GitHub Advisoryはこれらの悪性版に「patched versionsなし」としており、単一修正版番号を捏造しない。

確認・rollback。 清浄な環境への置換後、予期しない起動時フック・ネットワーク接続・秘密情報利用履歴を確認。旧イメージへのrollbackは行わず、隔離した以前のスナップショットは調査用としてのみ保存する。

未解明点。 個別環境で悪性wheelが実行されたか、どの秘密が流出したかはログやイメージ内容との照合が必要。

一次情報： Microsoft Security Research 2026-10-23（新しいタブ）、GitHub Advisory（2026-10-29更新）（新しいタブ）。

2. PHPリモートコード実行：特定機器の侵害痕跡が追加報告（P0）

事象。 PHPのCVE-2026-109618・CVE-2026-109619は未認証でPHPの実行権限の任意コード実行につながり得る。PHP Groupの初報は10月21日、JPCERT/CCの注意喚起は10月22日。JPCERT/CCは10月29日の更新で、特定バージョンのファイアウォール製品への攻撃が成功した可能性を示す証拠と、Linuxカーネル権限昇格の連鎖を追記した。 影響機器の詳細製品名は確認できていない。

対象・非該当。 PHP 8.2系8.2.35未満、8.3系8.3.36未満、8.4系8.4.27未満、8.5系8.5.12未満。8.1以前のEOL系は対応系列へ移行を検討。公開Web/PHP内蔵製品で攻撃入力が届く設定が優先。PHPを使わない静的サイトは本件のPHP実行経路に非該当。

被害。 Webアプリ実行権限での侵害、不正ファイル作成、内部ネットワークへの横展開。全Webサイトが侵害されたわけではなく、現実に悪用できるかはメモリ配置・OS・アプリ実装などに依存する。

対処。 公式修正版またはディストリビューション提供のbackportを適用。実際のWeb SAPI/workerの版を確認し、アクセスログ、長い不審なPHPSESSID cookie、multipart/form-data、前後のHTTP 500、メモリ上限エラー、ワーカー異常終了を点検。アップデートできない場合の session.upload_progress.enabled=0 は特定攻撃経路への限定的緩和策で、両CVEの完全修正ではない。

確認・rollback。 更新後にWebログインとupload等の機能試験、実稼働版確認、侵害痕跡の継続監視。回帰障害が起きても脆弱版で公開を継続せず、接続制限を保ったまま復旧する。証拠は保全。

未解明点。 被害機種や個別環境の侵害有無は未確定。1つのログ検出ルールで非侵害を証明できない。

一次情報： JPCERT/CC 2026-10-22公開・10-29更新（新しいタブ）、PHP Group 2026-10-21（新しいタブ）。

3. AWS Strands Agents Tools：prompt経由の環境変数秘密漏えい（P1）

事象。 AWSは10月28日12:30 PDT（10月29日04:30 JST）、CVE-2026-115415を公表。Strands Agents Toolsのenvironment toolが、LLMが選ぶtool schema引数からsecret maskingを無効化できていた。処理対象の外部文書やprompt injectionにより、agent hostの環境変数（cloud credential/API key等）がマスクなしで返る可能性がある。

影響条件・非該当。 strands-agents-tools >=0.1.0,<0.8.6でenvironment toolをagentにロードし、攻撃者がモデル入力へ影響を与えられる場合。packageだけを入れてtoolを使わない環境、または0.8.6以上で適切に修正された構成は報告経路に非該当。

対処。 strands-agents-tools 0.8.6以上へ更新。maskingはoperatorのみが設定可能となりenvironment toolはdeprecateされた。直ちに上げられない場合はenvironment toolをagentから外し、長期secretをプロセス環境に置かず、外向き通信を信頼先へ制限。toolが実際にロードされていた場合はアクセス可能だった認証情報の見直し・必要なrotationを権限者が検討。

確認・rollback。 導入版、agent toolリスト、機密値maskingがLLM側から制御できないことをstagingで確認。障害時は旧環境toolを戻さず、該当toolを除いた設計へrollback。漏えいの実際の有無は個別のログ・secret利用履歴調査が必要。

一次情報： AWS Security Bulletin 2026-154-AWS（新しいタブ）、GitHub advisory（新しいタブ）。

4. AWS Lambda：Brotli修正の段階適用と検証条件（P1）

事象。 AWSは10月28日15:00 PDT（10月29日07:00 JST）にBrotli CVE-2026-111497のAWSサービス対応状況を更新。LambdaのNode.js 22/24・.NET 8/10等で該当decoderを使う場合はランタイム更新が必要。Lambda基盤そのものが脆弱・侵害されたという意味ではない。

該当条件・非該当。 影響ランタイムで、外部由来の圧縮データを展開する関数等。Brotli decoderを実行しない関数や対象版を使わない環境には、この経路による被害は直結しない。

対処。 AWS管理のランタイム修正は段階配信。Node.js 24.22.1に別件の回帰問題があり、AWSは安定版へBrotli修正をbackport。ZIP関数は更新モード/実際に反映されたruntime versionを確認し、コンテナ形式では修正済みベースイメージへ再ビルド・再配置する。10月30日の自動配信予定を、すべての環境へ配信完了した確定証拠と混同しない。

確認・rollback。 CloudWatchのcold-start INIT_STARTにNode.js22 nodejs:22.mainline.v157以上、Node.js24 nodejs:24.mainline.v114以上と出ていることを確認。Node.js 24ではprocess.versionのみで確認できない。正常なBrotli処理テストを実施。問題が起きても脆弱なdecoderを外部へ公開するrollbackは避ける。

未解明点。 リージョン、関数、更新モードによる段階適用状況、独自コンテナやCI imageの更新完了は個々に検証が必要。

一次情報： AWS Security Bulletin 2026-155-AWS（新しいタブ）（10月28日PDT）。
