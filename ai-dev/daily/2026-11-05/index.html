優先：PyPI dbt-adapter の悪性版（該当環境のみP1）

GitHub Advisory Databaseが11月5日に公開し11月12日に更新したGHSA-jcpx-v43r-522mは、PyPIのdbt-adapter 0.0.0 / 0.1.0a2の2版をMalwareと明記しています。記載された挙動はインストール時またはimport時にIPアドレス・ユーザー名など基本的なホスト情報を外部送信することです。情報送信の可能性と実際の侵害確認は別であり、全利用者の秘密鍵流出や遠隔操作が実証されたという意味ではありません。

該当条件と安全な確認： 上記の完全なパッケージ名・版を実際に導入・importしたホストやCIです。dbt関連の似た名前を使っているだけでは該当しません。信頼できる管理環境からrequirements、lockfile、SBOMだけでなく、pip/pipxの導入履歴、仮想環境、ユーザー領域、ビルド済みコンテナ、CIランナーのキャッシュ、推移的依存、パッケージミラーも読み取りで照合します。名前が似ている依存を推測で同一視せず、未知のコードを確認目的で実行しないでください。

対処： 該当版を導入・実行した環境は隔離し、悪性パッケージを削除して再利用しないでください。Advisoryの「Patched versions: None」は安全な修正版が存在すると確認できていないという意味で、更新だけでは解消しません。信頼できる依存・隔離されたクリーン環境から再構築し、ミラー・キャッシュ・CI・コンテナの再混入を検査します。外部送信可能だった情報の範囲と資格情報へのアクセス条件を調べ、該当する資格情報は清浄な環境から失効・再発行します。正常スナップショットへ戻す際も同名・同版の再導入を防ぎ、実行を伴わない検証を優先してください。

GitHub Secret scanningの検出追加と誤検知削減（P2）

GitHubは11月5日、SpaceXをsecret scanning partnerに追加し、starlink_public_api_v2_secretの検出を導入したと公表しました。公開リポジトリで見つかったパートナー秘密は発行元へ通知され得ます。AWS、Google、OpenVSX、Pydantic Services等の検出器は誤検知を減らすため条件が更新されました。

実務への影響： secret scanningの警告が変化しても、検出数の増減だけで漏えい発生数の増減とは断定できません。公式の区別では、公開repoで検出されたPartner secretは発行元へ報告され、User secretはpublic/private repoでアラートとして扱われます。実際に有効なsecretの露出が確認された場合は発行元の案内に従って失効・ローテーションを優先し、必要に応じ履歴や派生物も整理します。履歴削除だけではすでに漏えいした資格情報は無効になりません。 該当する検出対象や設定がない場合は不必要な変更を避けてください。

CodeQL 2.27.4：解析・query metadataの変更（P2）

前日11月4日のCodeQL 2.27.4公開案内を、11月5日号にも継続的な運用確認事項として掲載します。Java/Kotlin・Rust・C/C++の誤検知改善と、複数言語のregex系queryからCWE-730 metadataを外す変更が説明されています。pack bundle/publish時はsymlink解決後にpack root外を参照するファイルを除外し警告します。

確認： カスタムCodeQL queryやCIでCWEタグ・警告件数を集計している場合に限り、2.27.4適用後の出力差とpack構成を検証します。GitHub公式はGitHub.comのcode scanningへの新版の自動配布と、GHES 3.24への収録予定を明記しています。GHESの実際の導入版は自組織の稼働環境で確認してください。

確認範囲と限界

掲載した一次資料を確認しました。すべてのベンダー、CISA KEV全件、実被害件数、個別の導入環境を網羅調査したものではありません。重大事象の不存在や、特定端末の感染を断定しません。
