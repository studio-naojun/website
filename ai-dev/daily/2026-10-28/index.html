AI開発・セキュリティ日報｜2026年10月28日号

Brotliの悪用確認、Tailscale 1.104.4の修正、GitHub Actionsの依存固定とNode.js 26 LTS移行。対象条件と確認・復旧方法を整理。

調査・編集：K.A.N.A.D.E.　／　確認時点：2026-10-30 08:30 JST

対象日：2026年10月28日（主に各社の現地発表日）。遡及調査：2026年10月30日08:30 JST。初回公開は10月28日ではなく、公開検証を終えた実際の日時を別記する。

本日の優先対応

  • P0（条件付き）：Brotli CVE-2026-111497。攻撃者が用意したBrotliデータを脆弱な実装で展開する公開処理を優先点検。10月27日のCISA KEV追加は既知問題の悪用確認で、10月28日の新規発見ではない。
  • P1：Tailscale 1.104.4。SSH forwarding、SSH server、Serve Unix backend、TLS複数mountの利用者は更新と接続回復手段を確認。単なる通常VPN接続だけで全項目に該当するわけではない。

1. Brotliデコーダーの悪用確認（P0：到達可能な該当実装）

起きたこと。 Google BrotliのC言語decoderの境界外書き込み「CVE-2026-111497」。細工された圧縮ストリームを展開した場合、異常終了・メモリ情報漏えい・任意コード実行の可能性がある。Google修正版は10月21日、JPCERT/CC公表は10月26日、CISA KEV収載は10月27日。収載は悪用の存在を意味し、どの利用者も侵害された意味ではない。

影響と非該当。 Brotli 1.0.3〜1.0.9、1.1.0、1.2.0など、該当C decoderを含む環境で攻撃者が送信可能なBrotliデータの展開が必要。Node.js、Bun、Python拡張や組込製品にも影響が及び得る。ライブラリが存在してもデコード経路がなければ本経路の成立は確認できない。

直ちに取る対処。 Brotli 1.0.10／1.1.1／1.2.1の各修正版系列、または製品ベンダーの修正リリースへ更新。Node.jsの公式セキュリティ版22.23.4、24.22.1、26.12.1などを選ぶ際は、後続のNode.js 24.22.2と個別ベンダーの回帰注意も確認する。コンテナやビルド済み成果物も作り直す。更新できなければ外部由来Brotliデータのデコード経路を制限する。

確認・rollback。 実行中のアプリとコンテナが修正済み実装を使うか、正常な圧縮データが処理できるかを確認。障害時も旧脆弱版へ無条件に戻さず、外部デコードを停止・制限した状態で修正方法を選ぶ。

未解明点。 静的リンク製品、ディストリビューションのバックポート、各プラットフォームへの配信状況は提供元に照会する。

一次情報： JPCERT/CC 2026-10-26（新しいタブ）、Google Brotli 1.2.1（新しいタブ）、CISA KEV（新しいタブ）（2026-10-27登録）。

2. Tailscale SSH・Serve：4件の修正を含む1.104.4（P1）

起きたこと。 Tailscaleは10月26日にTS-2026-014〜017を公開し、10月28日に修正版1.104.4を配布した。014はSSHのUnix socket forwardingがroot専用ソケットへ到達し得る問題、015は認証済みSSHセッションによるメモリ枯渇、016はServe Unix backendが特権ソケットへ到達し得る問題、017はTLS ServeのHTTP/2同時リクエスト間でcapabilitiesが混線し得る問題。

影響と非該当。 014はTailscale SSHとforwarding許可、015はTailscale SSH serverへの認証済み接続、016はServeのUnix socket backendとローカルoperator/書込権限、017はTLS Serveで権限要件が異なる2 mount以上・HTTP/2同時通信が条件。通常のVPN利用だけではこれらの条件を一律に満たさない。

直ちに取る対処。 該当機能を使うノードを1.104.4以上へ更新し、更新前に切断時の復旧手段を確保。014について更新できない場合、提供元が示す TS_SSH_DISABLE_FORWARDING=1 をtailscaledサービス環境に設定して再起動すればSSH forwardingのみを停止できるが、通信断の影響を評価する。

確認・rollback。 tailscale version と実際のSSH/Serve設定を確認し、更新後はVPN、SSH、Serveを順に疎通確認。旧版へ戻すなら問題のforwarding/Serve構成を閉じた状態のみ。SSHサーバーを使っていない人には014/015の直接対処は原則不要。

未解明点。 各端末の実行バージョン・機能の有効状態は端末ごとに実測が必要。侵害は確認していない。

一次情報： Tailscale Security Bulletins 2026-10-26（新しいタブ）、公式Changelog 1.104.4（新しいタブ）。

3. GitHub Actions lockfilesが正式公開（P2）

起きたこと。 GitHubは現地2026年10月28日、workflow dependency lockfilesをGAとした。tagやbranch参照を人間が読めるままにし、実行時はlockfileに記録したcommitを使用する。

該当条件・影響。 GitHub Actionsを利用し、外部Actionsやreusable workflowsの可変参照を管理したいリポジトリ。GitHub Free/Team/Enterprise Cloud等で利用可能。Actionsを使わない環境には直接影響しない。

対処。 GitHub CLIのgh actions-lock拡張で.github/workflows/actions.lockを生成・レビューし、対象workflowを段階導入する。Dependenciesを固定する前にコードと提供元を確認する。

確認・rollback。 CIでlockfileの同期検査と通常のworkflow成功を確認。問題がある場合は対象workflowのロック設定をPRで戻し、検証済みのcommit固定を別の方法で維持。lockfile自体は悪意ある依存コードを検出しない。

未解明点。 リポジトリ固有の権限ポリシー、既存Dependabotとの適合は導入時に確認。

一次情報： GitHub Changelog 2026-10-28（新しいタブ）。

4. Node.js 26 LTS移行と24系の更新（P2）

起きたこと。 Node.js 26.13.0は10月28日に「Lithium」LTSへ移行し、2029年4月末まで更新予定。同版は26.12.1から主にLTS表記メタデータ更新で、新たな重大修正の追加ではない。同日に24.22.2 LTSも公開された。

該当条件・影響。 Node.js 22/24から26へ移行する開発環境・サーバー・CI、特にLinux公式バイナリはNode.js 25以降でlibatomicが別途必要となる場合がある。Node.jsを使わない環境は非該当。

対処。 依存SDK・ネイティブモジュール・Docker/CIの互換性を段階検証し、現在のサポート対象LTSで安定運用できていれば即時一斉移行は不要。Brotliの修正取り込みも利用中の各系列で確認する。

確認・rollback。 node --version、lockfile/ビルド/テストを確認し、問題が出た場合は先に検証済みのサポート対象LTSへ戻す。

未解明点。 個別依存パッケージの互換性とネイティブビルドへの影響は利用者ごとに異なる。

一次情報： Node.js 26.13.0（新しいタブ）、Node.js 24.22.2（新しいタブ）（いずれも2026-10-28）。

5. GitHub Agentic WorkflowsがGA（P2）

起きたこと。 GitHubは10月28日、自然言語のMarkdownをActions YAMLに変換するAgentic WorkflowsをGAとした。Issue分類、CI失敗調査、ドキュメント更新などを自動化できる。

該当条件・影響。 GitHub Actions内でcoding agentを動かしたい利用者。標準で読み取り専用権限、sandboxとsafe outputsを備えるが、出力や権限設定のレビューは必要。既存workflowが自動切り替えされるわけではない。標準Copilot CLI engineにはCopilot licenseが必要。

対処。 導入前に権限と予算を確認し、まずread-only処理を少量動かして出力検証から始める。実運用への変更は通常PRとしてレビュー。

確認・rollback。 生成YAMLのpermissions、AI経由の出力、実行ログ、予算と実動作を検証。失敗時は新しいworkflowだけを無効化して既存CIを維持する。

未解明点。 組織ポリシー・課金・利用モデルは利用環境による。

一次情報： GitHub Changelog 2026-10-28（新しいタブ）。
