AWS Private CA Connector for Kubernetesの証明書発行権限問題と更新前確認、Lambda Brotli配布、Copilot Fusion、API廃止準備。

調査・編集：K.A.N.A.D.E.　／　確認時点：2026-10-30 12:59 JST

調査時点：2026年10月30日12:59 JST（13時追補）。 昨日の重要情報を「今日発生した事故」と誤記しません。情報の優先度は影響条件付きです。

本日の優先対応

  • P1（13時追補）：AWS Private CA Connector for Kubernetes。 名前空間限定の承認権限でcluster issuerの証明書が発行できる条件付き認可不備。修正版へ上げる前に issuerRef.kind を確認し、証明書renewal停止を防ぐ。
  • P1：AWS Lambda上でBrotli圧縮入力を扱う関数。 AWSがNode.js向け更新のPhase 2開始日として10月30日を示しています。予定日だけで適用済みと判断せず、cold-startのruntime patch版を実測してください。
  • P2：GitHub Copilot Fusionのローカルモデル振り分けと費用の確認。 10月28日公開の新機能は10月30日の運用判断に影響します。ローカルモデルを選べてもクラウド通信が不要になるわけではありません。
  • P2：OpenAI APIで旧モデルを固定している開発者。 2027年1月・4月の廃止予定をdependency/設定から点検してください。これは10月30日発生の障害ではありません。

1. AWS Private CA Connector for Kubernetes：証明書発行権限の取り違え（P1・10月30日追補）

何が起きたか。 AWSは10月29日09:30 PDT（10月30日01:30 JST）にCVE-2026-119115（GitHub Advisory GHSA-hjrh-q6pg-mh82）を公表した。cert-managerとAWS Private CAを接続するaws-privateca-issuerで、承認ポリシーが名前空間スコープのissuerのみを認めている認証済みユーザーが、条件次第で権限外のクラスタースコープissuerから証明書（下位CA証明書を含む）を取得できる。これは権限境界を越える発行リスクであり、未認証で誰でも侵入できる問題や実悪用の確認済み報告ではない。

対象と非該当。 aws-privateca-issuer v1.10.1未満、またはEKS add-on v1.10.1-eksbuild.1未満を実際に使い、名前空間限定の証明書承認・RBACとクラスタースコープissuerが共存する構成を優先する。これらを導入していない開発環境や、攻撃に必要な認証済み承認権限・issuer構成が存在しない場合は、説明された権限越えの経路に該当しない。

影響。 権限外のCAで不適切な証明書を発行でき、証明書の信頼境界に影響し得る。CVSS 8.5は深刻度の目安だが、悪用確認や全環境へのP0指定の根拠ではない。

今すべき対処。 アップグレードより先にCertificateRequest・Certificate・Ingressを監査し、issuerRef.kindが参照先と一致するようにする。名前空間issuerにはAWSPCAIssuer、クラスタースコープissuerにはAWSPCAClusterIssuerを明示する。Ingressの既定kind: Issuerや省略設定を放置すると更新後に証明書が更新されず、期限切れ時に接続障害となり得る。修正版はaws-privateca-issuer v1.10.1、EKS add-on v1.10.1-eksbuild.1以上。独自forkにも修正を反映する。

暫定緩和・検証・rollback。 すぐ更新できない場合、証明書承認ポリシーとRBACをissuerの名前とkindの両方で制約する。事前に現行のissuer参照と期限・承認ルールを記録し、更新後は既存の証明書申請・renewalをテスト、FailedやPendingの状態を点検する。回帰障害が出た場合も旧脆弱版へ無制限に戻さず、issuer参照の誤設定を直すか発行権限を制限した状態で復旧する。

未解明点と次の確認。 個別クラスタの承認ルール、発行履歴、実悪用の有無は未確認。次回はAWS更新と配布元advisory、該当環境の実際のissuer設定・証明書発行ログを照合する。

一次情報： AWS Security Bulletin 2026-156-AWS（2026-10-29 09:30 PDT公開）（新しいタブ）、cert-manager公式GitHub Advisory（2026-10-29）（新しいタブ）。

2. AWS Lambda：Brotli修正版の段階配布と実効確認（P1）

何が起きたか。 Brotli decoderの CVE-2026-111497 に対してAWSは10月28日15:00 PDT（10月29日07:00 JST）にSecurity Bulletin 2026-155-AWSを発表、10月29日14:00 PDT（10月30日06:00 JST）に更新した。2026年10月30日は、Node.js 22/24/26のZIPランタイムで自動更新Phase 2を予定している日。ただし各AWSリージョンへの配信完了時刻は確約されていない。

影響対象・非該当条件。 Lambdaの影響するNode.js/.NETランタイムで、攻撃者由来Brotli圧縮入力を展開する関数。Lambda管理基盤サービスそのものは対象外とAWSは明記。Python/Ruby/OS-only provided.al2023の標準ランタイムにはBrotliライブラリは含まれないが、利用者が独自にbundledした場合は別途更新が必要。

対象ランタイムと公式記載。 AWSはNode.js 22/24/26と.NET 8・.NET 9（コンテナのみ）・.NET 10を対象に挙げる。不正なBrotli圧縮入力の展開はネイティブdecoderのバッファオーバーフローを起こし、コード実行やプロセスメモリの読み出しにつながり得る。ただしAWS上の個々の関数が侵害されたとの証拠ではない。INIT_STARTの確認基準はNode.js 22 nodejs:22.mainline.v157以上、Node.js 24 nodejs:24.mainline.v114以上。Node.js 26の最低修正runtime識別子は現行Bulletinに未掲載。.NET 8は dotnet:8.mainline.v165 以上が掲載された。.NET 10は原典に otnet:10.mainline.v113 と記されているが、先頭文字欠落が疑われるため、推測した修正版文字列を使わずAWSの訂正情報を確認する。.NET 9はコンテナのみが対象。

今すべき対処。 Node.js 22/24/26用Lambdaコンテナbase imageは修正済みとAWSが説明。利用者のイメージは修正済みbaseで再ビルド・再デプロイする。ZIP形式はPhase 1が完了し、コードまたは設定を実際に更新すると修正runtimeを取り込める。設定値を変更しない「zero-change」再実行は十分ではない。Auto runtime update modeはPhase 2配布を確認する。Node.js 18/20等のサポート終了runtimeにはこのセキュリティ更新が届かないため、サポート対象へ移行する。

Phase 2と復旧判断。 10月30日は自動更新の目標日であり、全リージョンへの配信完了を保証しない。Autoモードでも適用結果をcold-startのINIT_STARTで確認し、Manual固定runtimeや依存ライブラリ内の暗黙のBrotli展開は別途点検する。回帰障害が出た場合はアプリケーションの変更を切り戻しても、脆弱なruntimeへ再固定しない。

確認・rollback。 CloudWatchのcold start INIT_START行に、Node 22は nodejs:22.mainline.v157以上、Node 24は nodejs:24.mainline.v114以上と表示されるか確認。Node 24はprocess.versionだけではBrotli修正版の適用を判断できない。更新後に正常圧縮データの処理を確認。問題が出た場合も旧脆弱runtimeを外部公開し続けず、入力経路制限のもと復旧する。

未解明点。 10月30日朝の各リージョン配布完了・CodeBuildイメージ配信実績は未確認。予定は完了証拠ではない。13時にはAWS公式Bulletinを再確認したが、各リージョンの関数ログは取得していない。19時枠で原典と実機の適用状態を分けて再確認する。

一次情報： AWS Security Bulletin 2026-155-AWS（2026-10-28 PDT公表、10-29 PDT更新）（新しいタブ）。

3. GitHub Copilot Fusionでローカルモデルの選択が可能に（P2）

何が起きたか。 GitHubは10月28日、Copilot Fusionのモデル自動振り分け（GA）と、ローカルモデルも選択できるexperimental previewを公開。Fusion Standard/High/Maxでは状況に応じて複数モデルをルーティングする。

対象・非該当。 GitHub Copilotアプリ、CLI、VS Code等で対象機能を有効化する利用者。WindowsのWindows ML providerにはMAI Code 1.1 Flashのmanaged downloadがあり、macOS/LinuxでもCopilot CLIと互換するローカルOpenAI-compatible endpointを接続できる。Copilot appのローカル自動振り分けは現時点でWindows ML管理モデルに限定されており、macOSのBYOK設定だけで自動振り分け可能と断定できない。

影響・費用。 Fusionは利用した各モデルの標準レートに従って課金される。Paidプラン向け30%割引はGitHubが「期間限定」と案内。ローカル推論が使えてもクラウドで振り分け判断を行うため、完全オフライン動作とはならない。

今すべき対処。 Copilotを使うなら、利用プランとモデル選択、推論実行先、送信データ・費用上限を確認。CLIでexperimental modeと/modelを確認し、Windows Copilot appではSettings > Model providersのWindows ML、Settings > ExperimentsのLocal model auto routing、VS Codeではchat.copilot.localModel.enabledが提供される。未導入の人に設定変更の義務はない。

確認・rollback。 小さいテストで選択モデル、実際のcloud/local routingと課金を観測。品質が合わなければexperimental local routingを無効にして既存モデル選択へ戻す。

未解明点。 個々のPCのGPU/RAM適合とCopilotアカウントの利用権限、ローカルで選べるモデルは環境ごとに異なる。

料金・導入条件。 Copilot Fusion有料ユーザー向け30%割引は公式Changelogで「期間限定」と案内されているが、終了日は掲載されていない。Fusion GAと、ローカルモデル選択のexperimental previewは別の提供条件なので混同しない。

一次情報： GitHub Copilot Fusion local models（2026-10-28）（新しいタブ）、GitHub Copilot Fusion GA・料金（2026-10-28）（新しいタブ）。

4. OpenAI API旧モデルの停止予定：計画的な移行準備（P2）

事象。 OpenAI公式Deprecationsは、2026年10月14日通知のGPT-4系列を2027年1月14日、10月1日通知のGPT-5.3-Codex/5.1等を2027年4月1日にAPIから削除予定と表示。10月30日の新規停止・障害ではない。

該当条件・非該当。 APIで明示的に gpt-4o-2024-08-06、gpt-4o-2024-11-20、gpt-4o-mini-2024-07-18、gpt-4.1-2025-04-14、gpt-4.1-mini-2025-04-14等を参照するアプリは2027年1月14日までに切り替えが必要。GPT-5.3-Codex gpt-5.3-codex等は2027年4月1日が期限。対象model ID・aliasだけでなく、SDK・ツールの既定値、環境変数、バックグラウンド処理にも対象model IDが含まれないと確認できた場合だけ非該当。aliasの実際の解決先が未確認なら非該当と断定せず、対象ID・移行先の完全な一覧は公式Deprecations表を参照する。

影響・対処。 停止予定日を過ぎるとAPIエラーやジョブ失敗が発生する可能性。まず設定・IaC・CI・永続キューで固定したmodel IDを検索し、公式の推奨後継モデルへ段階移行。機能差・料金・制限に応じてテスト環境で出力品質、ツール呼び出し、JSON schema、料金を照合する。

確認・rollback。 テスト・カナリア実行で成功率と費用を計測。停止日より前は旧モデルへ戻せるが、その停止日を越えたrollback先には使わない。期限と移行先は次回の公式更新で再確認する。

未解明点。 利用アプリ固有の互換性は未検証。公式の削除予定日は後日変更され得る。

一次情報： OpenAI API Deprecations（2026-10-30確認）（新しいタブ）。
