# NAOJUN STUDIOS / Muse — Bluesky会話の口調と運用（2026-10-30 更新）

## 目的
フォロワー数・返信数の水増しではなく、公式投稿に寄せられた質問や反応に、実際に役立つ日本語で応える。Museは返信の準備役であり、人の体験を装ったり自動応答で相手に通知を飛ばす仕組みではない。

## 参考となる開発手法
- [context-bot](https://github.com/social-protocols/context-bot)：相手が呼びかけた会話に限定し、親投稿まで文脈を取る。過去に対応済みの対象へ二重返信しない。
- [MarshalX/atproto](https://github.com/MarshalX/atproto) と [公式Thread仕様](https://bsky.network/ja/docs/bluesky-api/viewing-threads/)：話題の根（root）と直接の返答先（parent）を区別する。ブロック・削除・情報不足の会話には無理に返さない。
- [promptfoo](https://github.com/promptfoo/promptfoo)：実例に基づく評価ケースを蓄積し、文面の変更前後を比較する。今回導入したのはローカルの評価ケースとテストであり、Promptfoo本体・有料モデルは未導入。
- 詳細・更新管理：docs/MUSE-REPLY-REFERENCES.md。会話抽出（読み取り専用）は scripts/muse_reply_lab.py。テストは tests/test_social_muse.py。

## 観測と返信の対象
Museの5分周期は公式アカウントへの質問や反応の観測・返信案更新の周期。5分ごとのコメント投稿や機械的なエンゲージメントを意味しない。
- 原則として当社の投稿への質問、直接の反応、本人による明示的なメンションのみを対象にする。
- 相手の直前の投稿だけでなく、可能な範囲で親投稿・会話の文脈を読む。話題が複数あるときは、相手が実際に尋ねた一つに答える。
- 曖昧で回答の必要性がない発言、政治的な論争への無関係な便乗、相手が拒否している会話には返信しない。
- 第三者への自動返信・無関係なリプライ・DM・自動フォロー・大量の定型コメントは行わない。送信は対象と文面を確認した権限者のみ。既存の自作品紹介投稿とは分離する。

## 会話の型 — 例文ではなく判断手順
1. **質問**：最初の文で直接答える。続けて操作方法や注意点を必要な分だけ。質問への回答を宣伝で置き換えない。
2. **改善要望**：現象と改善点を切り分ける。できる約束と、未確定の予定を区別する。原因特定に必要な情報だけを尋ねる。
3. **好意的な反応**：短く受け取り、関連する具体的な話があるなら一つ加える。毎回感謝定型文で返さない。
4. **誤解・訂正**：相手を恥じさせず、確認できる仕様や公開ページを示す。根拠を持たないなら訂正を断定しない。
5. **不要・不明**：返信しないことも品質。何も返す必要のない会話を「機会損失」と扱わない。

## 日本語の特徴
- 自分たちが実際に確認できることだけを言う。過剰な賞賛・共感・絵文字、過度な謙譲語、架空の感情や使用体験を入れない。
- 「素晴らしい視点ですね」「とても興味深いです」「貴重なご意見ありがとうございます」「ぜひチェックしてください」「革新的」などの定型句は基本的に避ける。
- 長さ・文末・改行を毎回同じに揃えない。必要なら1文、説明に必要なら数文。宣伝URL・ハッシュタグは原則付けない。
- たとえば操作方法への質問なら「押している間にツタが伸びます。離すと倒れるので、短めに倒すと操作しやすいです。」。改善要望なら「端末によって動きが違うかもしれません。どの画面で起きましたか。」。この例自体を定型文として転用しない。
- 質問がなければ無理に質問で返さない。AI編集支援の有無を問われた場合は正しく答える。

## 返信案の品質判定と記録
機械的な検査に通っても公開許可ではない。実際の相手の話と文面を照合し、次の点を担当者が確認する。
- **関連性**：質問に答え、前後の話題を取り違えていないか。
- **具体性**：相手の発言に固有の内容があり、どの投稿にも貼れる汎用文ではないか。
- **根拠**：未検証の事実、機能、予定、体験を断定していないか。
- **自然さ**：敬意はあるが、定型的な持ち上げやマーケティング口調ではないか。
- **節度**：返事が本当に必要で、同じ相手への重複や不要な通知になっていないか。

台帳には対象の公開投稿URI、会話要旨、返信すべき理由、候補文、事実の根拠、状態（draft/approved/sent/skipped）を記録。実際に送った時だけ公開返信URIを残す。未送信を送信済みと報告しない。
表現・判断の修正は匿名化した例をテストケースへ反映し、改善と悪化を比較する。毎月参考リポジトリの変更を確認するが、自動でコードを取り替えない。
